# Proposal

## Why

Перед появлением Swift-исходников проекту нужны единые правила оформления и проверка, которую разработчик и CI выполняют одинаково. Это предотвратит расхождения в стиле и именах между модулями будущего приложения.

## What Changes

- Добавить конфигурацию форматирования и линтинга Swift с проверяемыми правилами именования.
- Описать соглашения для типов, протоколов, членов, файлов, тестов и SwiftPM targets.
- Добавить `justfile` с командой `just check`, объединяющей проверку форматирования, линтинг, сборку и тесты; отдельную команду для исправления форматирования.
- Запускать те же проверки в CI прямыми командами для каждого pull request и изменения основной ветки; `just` использовать только локально.
- Зафиксировать версии и способ установки локальных инструментов в документации проекта, а версию Swift — в CI.

## Capabilities

### New Capabilities

Нет: изменение касается инструментов разработки и не меняет поведение приложения.

### Modified Capabilities

Нет. Для изменения установлен `skip_specs: true`.

## Impact

Появятся `justfile`, конфигурация `swift-format`, документ с соглашениями и workflow GitHub Actions. Проверка применяется к `Package.swift`, `Sources/` и `Tests/` после появления SwiftPM-каркаса из изменения `scaffold-macos-app-architecture`. В текущем репозитории этих файлов и `just` ещё нет; доступен Swift 6.3.2 со встроенным `swift format`.
