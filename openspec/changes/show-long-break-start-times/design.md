# Design

## Context

Мотивация — в proposal.md. Сейчас SettingsPreviewView передаёт в DailyProgramView фиксированный workNumbers = 1...12; выбор привязан к DailyProgramDraft.longBreakAfter, расчёта вариантов нет. ProgramModule и SessionCoordinator — заглушки; таймер и сохранение ещё не реализованы. Presentation может зависеть только от SessionCoordinator, а координатор — от Program. Изменение build-scheduled-menu-bar-timer задаёт правила конца дня, замены обычного отдыха длинным и максимум двух длинных перерывов, но ещё не выполнено.

В опубликованных specs есть только application-shell. Новая самостоятельная capability не переписывает активные daily-program и interface-design-system. После реализации связанных изменений их контракты должны использовать общую проекцию, а не независимые формулы в SwiftUI.

## Goals / Non-Goals

**Goals:** чистый детерминированный расчёт вариантов, немедленная реакция на черновик, стабильный выбор по номеру, интеграция с текущим окном предпросмотра без изменения графа targets.

**Non-Goals:** запуск таймера, сохранение программы, переходы активной сессии, восстановление после выхода, добавление UI второго длинного перерыва. Расчёт принимает уже заданные другие длинные перерывы для совместимости с соседним изменением.

## Decisions

### Проекция допустимых позиций в Program

Добавить небольшой value-контракт входных параметров и чистый расчёт вариантов в Program. Это расчёт и валидация черновика, а не машина состояний таймера. Вход: начало в минутах локального дня, базовые часы, фокусирование, обычный отдых, длительность редактируемого перерыва и остальные заданные длинные перерывы с номерами работ. Выход: номер работы и минута начала для каждой допустимой позиции либо явная ошибка входа.

При отсутствии более ранних длинных перерывов: начало варианта после работы N = начало дня + N × работа + (N − 1) × обычный отдых. Каждый более ранний длинный перерыв добавляет свою длительность минус заменённый обычный отдых. Длительность редактируемого перерыва не сдвигает его собственное начало. Конец = начало + базовые часы × 60 + сумма полных длительностей всех длинных перерывов, включая редактируемый. Для каждого кандидата проверять полную работу и полный перерыв относительно конца и полуночи. Позиции, занятые другим перерывом, исключать. Валидировать вход перед арифметикой, чтобы не получать переполнение из внешних значений.

Не использовать Date(), ожидания и состояние активного таймера: это номинальное расписание настроек. Альтернатива — формула в SwiftUI — нарушает границы ответственности и создаёт вторую реализацию правил.

### Координатор передаёт готовые варианты интерфейсу

SessionCoordinator предоставляет @MainActor-запрос проекции редактируемых значений и снимок вариантов с номером и минутой начала. Модель Program не переэкспортируется в Presentation. Текст «С ЧЧ:ММ» и доступное описание «Длинный перерыв после работы №N, с ЧЧ:ММ» формирует Presentation из готовой минуты; оно не считает последовательность интервалов.

Если базовая модель программы появится в соседнем изменении раньше, переиспользовать её, сохранив этот контракт и тесты. В текущем каркасе достаточно минимального value-входа калькулятора: не нужно реализовывать сохранение или весь таймер как условие выполнения CR.

### Пересчёт при каждом изменении черновика

Заменить workNumbers в DailyProgramView на массив опций с устойчивым номером. Владелец черновика в SettingsPreviewView запрашивает проекцию у переданного координатора при открытии и изменении влияющих параметров. Пустой и ошибочный результаты — явные состояния. Операция синхронная и мала; debounce и фоновые задачи не нужны, устаревший результат после нового ввода не применяется.

Tag пункта меню остаётся номером работы. Недопустимый текущий номер остаётся видимым отключённым значением с локальной ошибкой; выбор не сбрасывается молча на первый пункт. Исправление параметров или явный выбор допустимой позиции снимают ошибку. Сохранение в предпросмотре остаётся отключённым по прежней причине — CR не добавляет фиктивное хранение.

Альтернативы «хранить время» и «автоматически выбирать ближайшее время» отклонены: обе меняют согласованную семантику привязки к работе.

## Risks / Trade-offs

- [Расчёт здесь и в будущей программе расходится] → единая чистая проекция в Program, примеры замены обычного отдыха в тестах и ссылка на неё при интеграции соседнего изменения.
- [Номинальную подпись принимают за прогноз текущей сессии] → краткое пояснение в help/доступном описании; фактические паузы и ожидания не входят в этот расчёт.
- [Смена параметров удаляет выбранную позицию] → сохранение номера, локальная ошибка и явное исправление.
- [Два перерыва меняют следующие позиции] → учитывать остальные заданные перерывы и исключать занятые номера без добавления нового UI в этом CR.

## Migration Plan

Пользовательских сохранённых данных ещё нет. Стабильный номер longBreakAfter сохраняется; вычисленные часы не добавляются в хранилище. Сначала добавить проекцию и контракт координатора, затем заменить данные меню и связать с черновиком. Откат возвращает подписи номеров работ, не меняя идентичность выбора и данные.
