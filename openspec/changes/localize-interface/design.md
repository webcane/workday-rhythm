# Проектирование локализации

## Context

`AppShell` формирует меню и заголовок окна через AppKit. Форма настроек, popover и компоненты шкалы используют SwiftUI, в том числе готовые значения `String`. SwiftPM собирает приложение для macOS 13+.

## Goals / Non-Goals

Один источник переводов и один выбор языка для AppKit и SwiftUI. Граница локализации проходит в Presentation, где состояния таймера и числовые значения превращаются в пользовательский текст.

## Decisions

- Поместить таблицы строк `en.lproj` и `ru.lproj` в ресурсы Presentation, задать `defaultLocalization: "en"` в SwiftPM. Локализованные таблицы и bundle ресурсов подходят для текущего запуска из SwiftPM и поддерживаемой версии macOS.
- При запуске сопоставлять упорядоченный список предпочитаемых языков macOS с языками ресурсов по основному языковому коду. Передавать выбранный язык в общий механизм поиска строк Presentation. Автоматический поиск только по основному bundle процесса оставил бы выбор языка ресурсов SwiftPM неявным и усложнил бы проверку порядка предпочтений.
- Использовать целые локализуемые шаблоны для динамических сообщений. Подставлять данные в Presentation и сохранять действующее представление времени шкалы и обратного отсчёта.

## Risks / Trade-offs

- Пропущенный ключ может привести к смешению языков. Проверить совпадение наборов ключей и подстановки в обеих локализациях.
- Длина перевода влияет на окно и шкалы. Проверить настройки и меню на обоих языках, включая ширину окна и подписи VoiceOver.

## Migration Plan

Язык определяется при запуске. Миграция сохранённых параметров дневной программы не требуется.
