# Design

## Context

См. [proposal.md](proposal.md) — Why. Репозиторий не содержит исходников, тестов или конфигурации сборки. Архитектурные границы взяты из [дизайна дневного таймера](../build-scheduled-menu-bar-timer/design.md): один процесс, явное ядро состояний, координатор, адаптер настроек и адаптеры macOS. Наблюдаемое поведение минимальной оболочки описано в [application-shell](specs/application-shell/spec.md).

## Goals / Non-Goals

**Goals:** компилируемые границы компонентов; одна запускаемая точка входа; проверяемое направление зависимостей; возможность расширить каркас без переноса логики из UI.

**Non-Goals:** реализация дневной программы, переходов таймера, сохранения пользовательских параметров, оповещений, автозапуска и упаковки релизного `.app`.

## Decisions

### Swift Package Manager как проверяемая основа

Создать `Package.swift` с локальными library targets и executable target `WorkdayRhythmApp`. Исходники разместить в `Sources/<Target>/`, проверки — в `Tests/`. Минимальный цикл разработки: `swift build`, `swift test`, `swift run WorkdayRhythmApp` на macOS с графическим сеансом. Указать минимальную версию macOS в manifest после проверки доступного SDK. SwiftPM позволяет собрать и проверить границы без генератора проекта и сторонних пакетов. Альтернатива — сразу создать `.xcodeproj`; она даёт готовую упаковку приложения, но добавляет формат проекта, который в текущем окружении с Command Line Tools нельзя проверить через `xcodebuild`. Релизная упаковка остаётся отдельной задачей.

### Разделение на targets и направление зависимостей

| Target | Ответственность | Разрешённые локальные зависимости |
|---|---|---|
| `Program` | Модели и проверка программы | нет |
| `TimerEngine` | Состояния и чистые переходы с явным временем | `Program` |
| `SettingsStore` | Изолированный доступ к UserDefaults | `Program` |
| `MacIntegration` | Системные события и сигналы | нет |
| `SessionCoordinator` | Последовательная обработка команд и вызов адаптеров | `Program`, `TimerEngine`, `SettingsStore`, `MacIntegration` |
| `Presentation` | Строка меню и окно настроек | `SessionCoordinator` |
| `WorkdayRhythmApp` | Создание зависимостей и жизненный цикл процесса | `Presentation`, `SessionCoordinator`, `SettingsStore`, `MacIntegration` |

`Program` и `TimerEngine` используют только Foundation и не импортируют AppKit или SwiftUI. `Presentation` не импортирует `TimerEngine` или `SettingsStore` напрямую. `Package.swift` служит исполняемым правилом графа зависимостей; отдельная проверка запрещённых импортов защищает границу, если targets позже объединят. Альтернатива — один target и соглашения по каталогам — не обеспечивает проверку графа компилятором.

На этапе каркаса каждый target содержит минимальный осмысленный публичный контракт либо тип-заглушку, необходимую для компиляции, без имитации работающего таймера. Команды реальной сессии добавляются отдельным изменением.

### Оболочка на AppKit

Executable создаёт `NSApplication` с режимом accessory и один контроллер оболочки. `Presentation` устанавливает `NSStatusItem` с меню «Настройки» и «Выход» и открывает отдельное `NSWindow` с текстом о будущих параметрах. Сильная ссылка на контроллер и окно хранится в жизненном цикле приложения. Это даёт реально запускаемое меню без дополнительной упаковки. Альтернатива — `MenuBarExtra` на SwiftUI; для начального CLI-запуска AppKit даёт более прямой контроль над жизненным циклом и не требует предположений о `.app`-bundle.

### Граница хранения

`SettingsStore` остаётся единственным местом будущего доступа к UserDefaults. В [исходном дизайне](../build-scheduled-menu-bar-timer/design.md) UserDefaults выбран явно, тогда как подпись к [временной диаграмме](../build-scheduled-menu-bar-timer/specs/daily-program/timeline.md) ещё упоминает JSON. Для нового каркаса действует решение из дизайна; исправление диаграммы относится к исходному изменению. Не сохранять данные сессии и не вводить файл JSON.

## Risks / Trade-offs

- Запуск через `swift run` создаёт процесс с пунктом меню, но не релизный `.app` → описать запуск как режим разработки и проверить его вручную в графическом сеансе macOS.
- Текущие Command Line Tools могут собрать Swift-код, но `xcodebuild` недоступен → проверить `swift build` и `swift test`; ручной запуск отметить отдельной проверкой на машине с графическим сеансом.
- Пустые модули могут разрастись фиктивными API → оставить только контракты, нужные для связывания; поведение таймера добавлять по отдельным спецификациям.

## Migration Plan

Миграции нет: исходников и пользовательских данных в репозитории пока нет. Откат состоит в удалении новых `Package.swift`, `Sources/`, `Tests/` и документации каркаса до начала реализации таймера.
