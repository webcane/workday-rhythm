# Proposal

## Why

Значимые наборы вариантов, визуальные параметры и связанные геометрические числа сейчас местами повторяются или остаются безымянными рядом с представлениями. Это создаёт несколько источников истины и позволяет отображению, проверке и управлению одним значением расходиться при последующих изменениях.

## What Changes

- Дополнить соглашения Swift правилами выбора единственного типизированного владельца для предметных ограничений, визуальных токенов и локальной геометрии компонентов.
- Устранить повторение наборов вариантов и связанных литералов в текущем коде, не меняя наблюдаемое поведение интерфейса.
- Передать допустимые длительности рабочего дня владельцу предметного правила и использовать один источник для отображения, навигации и проверки.
- Сосредоточить общие цвета, радиусы и отступы в `DesignTokens`, а специфичную геометрию составных компонентов — в именованных частных `Metrics`.
- Добавить тесты модели и компонентов там, где они подтверждают границы, значения по умолчанию и использование единого правила.

## Capabilities

### New Capabilities

Нет. Изменение не добавляет наблюдаемого пользовательского поведения.

### Modified Capabilities

Нет. Существующие требования интерфейса и дневной программы сохраняются.

## Impact

Изменение затронет `docs/code-style.md`, владельца правил дневной программы, SwiftUI дизайн-систему и соответствующие XCTest. Внешние конфигурационные файлы и новые зависимости не добавляются; пользовательские настройки, сохранённые данные и публичное поведение приложения не меняются.
