# Proposal

## Why

Переход между работой и отдыхом легко пропустить, если заметить только строку меню. Пользователю нужны заметные настраиваемые сигналы завершения интервала и одно ненавязчивое утреннее предложение начать запланированный день.

## What Changes

- Добавить центральный экранный сигнал завершения работы и отдыха с выбранной системной мелодией macOS, настраиваемой длительностью показа и независимым повтором звука.
- Ввести отдельные сохраняемые настройки сигналов с устойчивым идентификатором мелодии; при недоступности сохранённой мелодии использовать системный звук по умолчанию.
- Добавить в существующее окно настроек toolbar-панель «Сигналы» рядом с «Рабочим днём», без новых окон, sidebar или нижнего tab bar.
- Добавить отключаемое по умолчанию утреннее местное уведомление с действием «Начать день», однократное для каждого календарного дня и согласованное со сном, пробуждением и первым запуском приложения.
- Сохранить запуск дня только после явного действия пользователя и повторной проверки допустимости на текущую дату.

## Capabilities

### New Capabilities

- `timer-alerts`: настраиваемый экранный и звуковой сигнал завершения интервала.
- `morning-start-notifications`: однократное утреннее предложение начать рабочий день через системное уведомление.

### Modified Capabilities

Нет: требования дневной программы, переходов таймера и существующей оболочки не меняются.

## Impact

Потребуются модель `AlertSettings` в предметном слое, расширение `SettingsStore`, публичные адаптеры AppKit/UserNotifications в `MacIntegration`, маршрутизация в `SessionCoordinator`, а также панель SwiftUI в существующем окне настроек. Контракты ядра будут передавать только устойчивые значения (например, идентификатор мелодии), а не типы AppKit. Автоматические XCTest охватят модель, хранение, fallback звука, длительность, повтор, дедупликацию и разрешение уведомлений; macOS-сценарии подтвердят UI и системную интеграцию.
